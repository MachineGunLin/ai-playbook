# Prompt 模板库

> 全库唯一出处。其他文件只链接到这里，不复制。
> 每块独立复制整段发送；`[...]` 按任务替换。

## 通用

### 先提问（Grill me，动手前对齐）

```
在动手前，先向我提问对齐，不要写代码：
1. 你理解的目标和验收标准是什么
2. 影响范围（会动哪些文件/模块，哪些明确不动）
3. 你的做法（简述步骤，不超过 5 步）
4. 需要我拍板的分歧点
问完等我回复再继续。
```

### 先调查不执行（只读、禁改）

```
只调查、不修改任何文件：
1. 先讲清 [...问题...] 的调用链和根因定位到哪几行（贴文件:行号）
2. 列出 2 个候选修法及各自风险
3. 停在这里等我选，不要自己动手改
```

### 自主执行（长任务放手跑）

```
目标：[...一句话目标...]
约束：只动 [...目录...]，不动 [...]；跑通 [...验证命令，如 npm test...] 才算完。
做法：拆成检查点清单，做完一项勾一项；中途缺信息先按合理假设推进，并记下来最后统一对。
结束时给我：改了哪几个文件、验证结果、还有什么没做。
```

### 最终验收（收尾固定动作）

```
收尾验收，逐条回答：
1. 改了哪几个文件（列表）
2. 跑了什么验证（贴命令+结果）
3. 验收标准哪条没达到、为什么
4. 回滚方法（一句话）
有一条答不上来就说答不上来，不要糊弄。
```

## Coding

### Debug（假设→验证→修复）

```
现象：[...现象 + 复现步骤...]
相关日志/报错：
[...粘贴原文...]
要求：
1. 先给根因假设（按可能性排序），不要上来就改
2. 每个假设配一条验证命令
3. 验证通过后再修，修完重跑验证并贴结果
```

### Code Review（只审不改）

```
审查下面这批改动（diff/文件见上下文），你只审不改：
1. 正确性 bug（逐条贴文件:行号 + 原因）
2. 边界条件和异常路径遗漏
3. 安全问题（注入、越权、密钥）
4. 按严重程度排序；没问题的直接说通过，不要硬挑
```

## 协作

### 接手上一个 Agent（跨会话/跨工具）

```
接手上一棒，上下文如下：
- 原目标：[...]
- 已完成：[...]
- 已验证：[...命令及结果...]
- 未完成/卡点：[...]
- 相关文件：[@文件1 @文件2]
要求：先复述你的理解，确认无误后再继续；不要重复已验证过的工作。
```

## Research

### Web Research（要引用、能回查）

```
调研 [...主题...]，要求：
1. 只用近 3 个月的一手来源（官方文档/发布说明/原帖），每个结论带链接
2. 区分“官方已确认” vs “社区经验” vs “你没查到的”
3. 没查到的直接写没查到，不要编
4. 最后给 5 行内的行动结论
```

## Learning

### Socratic 家教（只问不给答案）

```
你是我 [...科目...] 的家教，规则：
1. 不直接给答案，只提问引导我自己推出结论
2. 我答错时先指出错在哪类（概念错/推理错/计算错），再给一个更小的提示问题
3. 每 3 轮小结一次我已掌握和未掌握的点
4. 全程结束前出一道变式题验收
主题：[...]
```

### Feynman 自测（讲出来才算懂）

```
我要用 Feynman 法自测 [...主题...]：
1. 先让我用自己的话讲一遍（不要打断）
2. 然后逐段追问：这里为什么成立？反例是什么？和 [...相邻概念...] 的区别？
3. 凡我用术语糊弄过去的地方，当场点名
4. 最后给我打分：复述/理解/迁移三项各 1-5 分，并指出最弱一环
```
