# Skills：值得沉淀的才做成 Skill

## Skill vs Prompt vs 命令

| 形式 | 谁触发 | 适合 |
|---|---|---|
| Prompt（一次性话术） | 人每次复制 | 低频、每次都不同的活 |
| 命令（`/xxx`） | 人输入触发 | 高频、流程固定的活 |
| Skill | 模型按 description 自行触发 | 领域知识、重复流程，不想每次提醒 |

三者可共存：同一流程可以既写命令（人触发）又写 skill（模型自触发）。

## 什么值得做成 Skill

- 一周用两次以上，且每次都要重复同一套约束/步骤。
- 需要领域知识（某框架的坑、某仓库的发布流程），而不是通用能力。
- 出过错、且错因是“模型不知道某条规则”——把规则写进 skill 比每次口头提醒可靠。

## 怎么写才能稳定触发

- description 写成触发句（“当任务涉及 X 时加载”），这是唯一的发现信号。
- 一个 skill 只干一件事；标题和正文第一句就说明适用场景。
- 长度克制：常驻 skill 进每轮 context，臃肿的 skill 等于慢性失血。

## 哪些知识长期沉淀

- 沉淀：构建/测试命令、代码规矩、发布 checklist、踩过的坑（进 `AGENTS.md` 或 skills）。完整落盘规则见 [memory.md](memory.md)。
- 不沉淀：当次任务的临时结论、日志 dump、猜测——留在会话里，用完即弃。
